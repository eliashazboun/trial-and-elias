# Decisions

- **Website integration authorized:** the owner's follow-up explicitly requests integration like the dungeon. Use apps/blackjack-trainer, /blackjack-trainer/, the root registry/build and a Playground card. This supersedes the original standalone-only destination. Production push/deployment remains excluded.
- **Engine first:** deterministic command/event architecture keeps rules and money independent of visual frame rate. Integer half-chip units enforce exact odd-wager blackjack and insurance arithmetic.
- **Persistence:** one authoritative versioned snapshot plus ownership, committed with revision and lease checks. Separate per-domain object stores were considered; the single snapshot makes wallet/round atomicity easier to audit. Trade-off: a near-budget history entails larger writes; benchmark on target phones before raising retention.
- **Concurrency:** Web Locks plus database lease/CAS. The lease-only initial implementation delayed immediate refresh; the browser regression exposed it and Web Locks now safely reclaim a new document's writer lease. Fallback recovery remains documented at up to eight seconds.
- **Split order:** sequential first child then siblings; equal-value ten ranks may split. These are the specification's selected defaults.
- **Dealer reveal:** always reveal the hole card after the round, including all-bust rounds. Do not make unnecessary dealer draws. Only newly exposed physical cards affect Hi-Lo.
- **Total-dependent strategy:** S17/DAS/no-surrender charts for one, two and 4–8 decks. The three larger deck counts share the validated conventional table. Two-deck soft 18 versus ace follows the reference's number-of-cards convention: hit with two cards, stand with more. No count deviations or live shoe-composition optimization are introduced.
- **Graphics and audio:** original generated textures and synthesized sounds avoid hotlinked assets and uncertain redistribution rights. All dependencies have bundled notices. Card artwork is replaceable.
- **Ads:** disabled production provider; legitimate reward events require an idempotent persisted receipt. No provider, credentials, consent SDK or tracking script is activated. Local mocks are imported only by tests.
- **Dependency patching:** upgraded Zod to 4.6.7 and the shared test runner to Vitest 4.1.12 after audit findings. The integrated dungeon's devDependency version changes; gameplay source is untouched. Full regressions run on the patched runner.
- **History and export:** 100–5,000 detailed rounds plus a 25 MB soft detail budget, lifetime aggregates preserved. Export replaces data only after validation and confirmation; no reward merge. CSV fields identify half-chip units and neutralize spreadsheet formula prefixes.

## Gameplay overhaul — 2026-11-25

- Stable React controls now own table input. Phaser only renders committed projections; shared pure geometry positions both layers. Sprite destruction/recreation can no longer replace a betting hit target during rapid input.
- Betting intents capture the selected denomination and serialize against current committed state. Already-queued simple betting intents are reduced in order and saved together, avoiding an IndexedDB write backlog without a timer, click debounce or arbitrary input lock. Deal/rules are barriers. Failed intents do not alter wallet state; CAS and writer ownership remain authoritative.
- Placement history and normalized visual stacks are separate. Greedy denominations are display-only; remove pops the latest placement for one spot and global Undo restores its preceding configuration. Exact totals remain half-chip integers. Expanded previews are bounded for large imported values.
- Rebet, doubled configurations and Rebet & Deal validate the entire candidate before publishing it. Initial main limits are 10–50,000 per position; side limits remain 1–100, and legal split/double exposure is separate from initial limits.
- All hands, including waiting one-card split children, are rendered from the real projection. No cards are drawn for appearance. Dedicated DOM ranks and Hi-Lo badges sit above card sprites; the hidden dealer card has no badge.
- Strategy countdown begins after presentation and restarts for each actionable decision. Enabling the setting is recorded separately from actual recommendation exposure. The eye mask removes the running answer from the displayed DOM; counting state itself is unaffected.
- Existing database version and backup compatibility remain. Legacy keyboard mappings acquire unused keys for the two new denominations instead of resetting custom shortcuts.

## Running-count guessing — 2026-11-25

- Count visibility is now authoritative game state, mirrored into preferences only after the IndexedDB commit. Legacy saves initialize from the existing visibility preference with zero hidden-round credit; current saves use the saved game value on refresh. Existing schema-v1 backups acquire safe defaults.
- A round earns one credit only if it began hidden, stayed hidden and reached complete. Split children/positions/actions do not earn extra credit; canceled rounds earn none. A reveal mid-round invalidates that round's credit. A fresh shoe does not break a continuously hidden streak.
- An eligible reveal stores a unique pending peek ID and clears progress/unfinished feedback. The subsequent hide commits a ledger debit and consumes the ID atomically. Repeated same-state commands, rerenders and refresh cannot consume it again. Ordinary pre-eligibility toggles are free.
- The debit is min(100 chips, uncommitted bankroll), in integer half-chip units. If remaining bankroll cannot cover pending betting reservations, all pending placements and their Undo snapshots are cleared in the same transaction; committed stakes remain intact. Peek debits remain outside blackjack round/session win-loss net, including canceled rounds.
- Both inline and existing running-count submissions enforce the gate in the engine and use the current committed shoe count. The input has no answer-derived value, placeholder or validation metadata. Inline feedback omits the actual count and never reveals the indicator. Guess records use existing count-check statistics, including assistance flags.
- Existing exercise reveals and true-count exercises expose the running count through the same visibility transition. Skipping an exercise no longer displays its answer. Existing exercise feedback waits for persistence.
- Balance/gameplay/education resets clear streak progress; pending peeks survive partial resets. Full reset creates a fresh table. History/achievement-only resets preserve training state. Explicit backup restore retains its saved training state.

## Hand totals and settlement presentation — 2026-11-25

- Wager drift came from layout.wager.x = hand.x + hand.width - 27. It now uses the center of the actual card fan bounds; total labels share that center. Each split child keeps its own stake, result and stable ID. Totals use the existing evaluate function (including soft totals, naturals and busts).
- Side-bet stacks were gated by the pre-deal betting state. The engine correctly moved their original placements into round.positions, but the UI only displayed aggregate result text after dealing. The table now renders each saved position/kind in its own designated area with its original amount and independently resolved result.
- Projection snapshots optionally carry sideResults. This is a presentation-only extension; schema-v1 snapshots without it remain valid. Side events enter the existing presentation timeline, preventing results from appearing before their corresponding deal/settlement step. Rules, paytables, shuffling and ledger calculations are unchanged.
- Wager visuals consume authoritative stake/net/outcome. A loss moves the original stake to the visible dealer collection area. A win returns stake plus actual net toward the player; pushes return only stake and refunds are labeled separately. Notification amounts show net only. No timer or animation callback dispatches a financial command.
- Wager animations run once on an unresolved-to-resolved transition. Already-resolved mounted/reloaded wagers render cleared, resize does not restart movement, and reduced-motion/instant presentation skips flights. Results stay visible until the next round transition.
- The existing command queue waits through a 1.5-second final-result reading interval. An explicit next-round request can queue immediately but cannot cancel this interval or erase outcomes immediately. Existing stored completed rounds do not acquire an extra delay on load.
- Compact hand geometry places counting badges in a dedicated layer inside each card face below its rank, reserving space for centered stakes and totals. Side bets reserve their own row. Between-round controls use the table's bottom space so they do not overlap completed-hand labels.
